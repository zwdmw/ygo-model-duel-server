# 模型与运行时契约

## 支持范围

这不是一个能加载任意游戏王权重的通用服务器。当前策略侧基于 JAX/Flax `RNNAgent`，
支持本项目结构化编码模型及 `decision-v1` 架构。训练所用动作空间、历史长度、卡号映射、
语义张量及参数树必须匹配。

`195M`、`305M`、`640M` 等标签表示训练步数，不是参数量。

登记工具要求：

| 输入 | 内容 |
|---|---|
| `.flax_model` | Flax 序列化权重，单文件小于 256 MiB |
| 同名 `.json` sidecar | 训练时导出的真实架构参数，不是事后猜测 |
| `--training-project` | 对应训练工程的资源目录 |
| `--steps` | 权重实际训练步数 |
| `--label` | 可选步数标签，例如 `640M` |

训练项目必须有：

```text
assets/locale/en/cards.cdb
assets/structured/frozen_semantics_v1.npz
scripts/code_list.txt
```

这些文件和部署资源按 SHA-256 严格配对。不能重新排序 `code_list.txt`，
不能用“同样数量的卡”替代同一份卡号索引，也不能用另一批语义数据解释已训练参数。

sidecar 的 `schema` 必须是 `ygo-training-checkpoint/v2`，`architecture` 是
`structured`、`structured-v1` 或 `decision-v1`，`model_args` 是实际训练时模型构造参数。
可选 `semantic_shape` 会在策略加载时进一步核对。登记只做静态验证，
`preflight --warmup` 才实际验证参数树、形状、原生环境与一次推理。

旧模型没有 sidecar 时，先从训练配置恢复真实参数。只有确认训练使用项目完全相同的默认结构时，
`model_args: {}` 才有意义；不要为了通过登记检查填一个空对象。

原生发布包包含经过检查的 `.so` 与 `native-build.json`；外服编码器还核对其中的
`source_hashes.ygopro.h`。更换引擎或观察编码后，应重新验证契约和对局，不是仅更新哈希。

## 新的登记目录

`tools/deploy.py register-model` 会：

1. 校验训练资源与运行时是否匹配。
2. 将权重复制到 `model/catalog/<sha256>.flax_model`，复制架构 sidecar。
3. 记录权重、sidecar、资源的哈希到 `room/admin/models.json`。
4. 首次 `--activate` 时写入房间活动模型描述。

登记列表与旧的训练评测 Top 10 模式相互独立：

- `agent.json` 设置 `model_catalog`：使用显式登记模型，不给出虚构胜率。
- 设置 `model_run`：保留历史评测目录模式，要求对应评测产物完整。
- 同时存在时优先使用 `model_catalog`。

登记新模型不会自动切换正在进行的对局。通过面板切换时，继续使用原有空闲窗口、
加载检查及失败回滚机制。

## 私服与外服的区别

私服由本地原生规则引擎执行对局；每局建立独立环境与循环状态，共用常驻策略推理进程。
外服由对方服务器执行规则，模型进程重建网络可见的观察并发送动作。

网络玩家不能获得对手隐藏卡、隐藏选择或打乱后的牌组顺序。
因此网络观察适配**不等同于原生编码的严格复制**。合法动作、可结束的对局或有限 logits
只证明某个集成路径可执行，不证明模型能力、胜率或训练/部署观察完全一致。

已包含旧版官方模型的外服策略适配代码；它使用不同的输入约定。
新的通用登记命令不自动把官方或任意其他架构认作结构化模型，不能通过改标签混用。

## 卡池

Release 同时带有该快照配套的本地卡池与独立外服卡池。
`room/card-pools/current.json` 通过哈希选择外服池；它不自动改写私服原生环境。
自有模型训练卡池不同的时候，不应保留一个与其基础索引不匹配的外服池。

需要回到基础池时，在新实例中移走 `room/card-pools/current.json` 后再预检；
外服客户端会使用基础运行时卡池。不要在活跃对局中修改资源。
需要新增卡时，应按 `outbound/pool_assets.py` 的追加索引、语义形状及清单校验契约重新构建，
不能简单替换一个下载来的 `cards.cdb`。

## 验收

建议依次验证：静态预检、真实策略预热、隔离的本地自对局、受控客户端联机、
受控外服一局、录像与中断清理。生产健康接口 `ready` 不是完整对局验收。
运行包中不附带原作者的训练权重或账号；必须自行提供有权使用且与契约匹配的模型。
